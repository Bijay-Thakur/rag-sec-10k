## Phase 4 — SEC XBRL facts and deterministic reasoning

1. Build a server-side `companyfacts`/`companyconcept` adapter using the existing SEC transport policy: allowlisted HTTPS paths, authentic contact, shared conservative rate limiter, bounded response/timeouts/retries, no unsafe redirects, cache and raw checksum. Follow [SEC XBRL API documentation](https://www.sec.gov/search-filings/edgar-application-programming-interfaces). SEC APIs cover non-custom taxonomy, entity-wide facts; do not infer that a missing API fact means the filing lacks the disclosure.
2. Normalize facts with CIK/accession, taxonomy/concept, unit/value, start/end, fiscal year/period, form, filed date, frame where available, raw response ID and active revision. Define explicit as-filed/as-of and amendment/restatement precedence. Keep instant and duration facts distinct. Preserve source provenance and avoid duplicating the same economic fact as separate periods.
3. Implement reviewed numeric formulas with decimal arithmetic and typed operands: YoY, margins, ratios and CAGR where valid. 4. Integrate typed intent routing for fact lookup, calculation, narrative and cross-filing comparison. Every displayed number must identify reported versus calculated status, formula, units, filing/period and source. If the fact basis is incomplete, return partial or unavailable with the reason.

**G4 tests:** 10-K/10-Q, amendment and restatement cases; fiscal/calendar boundaries, instant/duration distinction, units/scales, custom-taxonomy absence, table footnotes, duplicate facts, numerical tolerances, and malformed SEC responses.
